## F-2. 公開後に壊れたとき（元に戻す）
1. Vercel → Deployments で、前の Production のデプロイ（動いていたもの）を開き、「Instant Rollback」を押す。アプリはすぐ前の版に戻る。Hobby プランで戻せるのは、1つ前の Production のデプロイだけ。
2. main も元に戻す（戻さないと、次のデプロイで壊れた版がまた出る）。壊したマージのコミットを、星凪が Pull Request で打ち消す：
   ```bash
   git switch main && git pull
   git log --oneline --merges -5          # 壊したマージのコミット（<merge>）を探す
   git switch -c fix/revert-（短い説明）
   git revert -m 1 <merge>                # マージで入った変更だけを打ち消すコミットを作る
   git push -u origin fix/revert-（短い説明）
   ```
   Pull Request を出し、3人で読んでから、創大がマージする。
3. 直したコードは、いつもどおり Pull Request で main に入れる。
4. Firestore は無料の Spark プランなので、バックアップが無い。データは元に戻せない。本番では、データを消す・まとめて書き換えるスクリプトを実行しない（`--reset` も公開後は使わない）。例外は、12/8〜12/9 の測定で創大が動かす `scripts/seed-200.ts`（サブスクが0件のテスト用アカウントに200件入れるだけ。`subwatch/` で `node --env-file=$HOME/secrets/cron.env --import tsx scripts/seed-200.ts --email （テスト用アカウント）`。`AIプロンプト/バグ修正.md` の「05-05」）。

## F-3. 残ったデータの点検（運用。結愛〔Firebase の持ち主〕。12/2〔4限後半の15分〕と 12/9。決まりの一覧 C-12・B-7・B-9）
