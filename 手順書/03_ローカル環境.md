# 03 ローカル環境（全員。11/12）

## 1. 必要なもの
- Node.js 22 LTS（`node -v` が v22 で始まる。Vercel も 22.x にする）。無ければ nvm で入れる：`curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash` の後、ターミナルを開き直して `nvm install 22 && nvm alias default 22`
- Java 21 以上が必須（Firebase の Firestore Emulator は、古い Java では起動しない。`java -version`。無ければ `sudo apt install -y openjdk-21-jre-headless`）
- firebase-tools：`npm install -g firebase-tools`（nvm で入れた Node.js なので `sudo` は付けない）
- Git と GitHub CLI（`sudo apt install -y git gh`）、自分が使うAI（Claude、ChatGPT など）
- Python 3 と openpyxl（設計書テキストを作り直すとき。`sudo apt install -y python3-openpyxl`）

## 2. リポジトリを取ってくる
最初に一度だけ、Git の名前とメールアドレスを入れ、GitHub にログインする。
```bash
git config --global user.name "（自分の名前）"
git config --global user.email "（GitHub に登録したメールアドレス）"
gh auth login        # gh は 1 で入れた。gh を使わないときは、push のときにパスワードの代わりに Personal Access Token（PAT）を入れる
```
結愛と創大は、先に GitHub の招待を受けておく（手順書 02 の 1 の 3）。PAT を使うときは **classic**（`repo` にチェック）で作る。fine-grained の PAT は、創大の個人のリポジトリへ push できないことがある。
```bash
git clone https://github.com/itc-s24008/SubWatch.git
cd SubWatch
```

## 3. 準備する（04-01 の土台が main に入った後）
```bash
cd subwatch
npm ci
npx playwright install --with-deps chromium   # ブラウザと、動かすのに要る部品を入れる（sudo のパスワードを聞かれる）。11/17 の3限に画面テストを書く結愛と星凪は、11/12 のうちに（結愛は 1〜2 の後、星凪は Vercel の準備の後）土台を待たずに `npx --yes playwright@1.64 install --with-deps chromium` を済ませておく（版は機能設計書「0.実装構成」の `@playwright/test` と同じ 1.64 系。違う版だと、ここでブラウザをもう一度取ってくる。同じ版なら速く終わる）
# sudo が使えないとき：`npx playwright install chromium`（ブラウザだけ。sudo はいらない）を行い、画面テストが部品の不足で動かなければ、sudo を使える人に `npx playwright install-deps chromium` を頼む（未確認）
cp ../設定ファイル/.env.development.example .env.development.local
npx next telemetry disable   # 任意。Next.js が利用状況を送るのを止める（試し実行では止めて動かした）
```
`../設定ファイル/` は、リポジトリの中の `設定ファイル/`（配られた `05_設定ファイル（CLAUDE.md など）/` を手順書 02 の 2 で名前を変えて入れたもの）。`ls -a ../設定ファイル` で `.env.development.example` があることを確かめる。
**ローカルの開発は、これだけで動く。本物の鍵はいらない。**
- `.env.development.local`：Emulator 用のダミーの値（Push のテスト用の鍵も入っている）。`npm run dev` はこちらを優先し、接続先も Emulator になるので、本物の Firebase に触らない。テスト（`npm test`、`npm run test:emulator`、`npm run test:e2e`）も、このファイルを読む。次の変数が入っている：NEXT_PUBLIC_USE_AUTH_EMULATOR、FIREBASE_AUTH_EMULATOR_HOST、FIRESTORE_EMULATOR_HOST、NEXT_PUBLIC_FIREBASE_PROJECT_ID=demo-subwatch、空の FIREBASE_SERVICE_ACCOUNT_JSON。**消さない。**

## 4. Emulator と画面を動かす
ターミナル1（リポジトリの直下）：
```bash
firebase emulators:start --only auth,firestore --project demo-subwatch
```
ターミナル2（`subwatch/`）：
```bash
npm run dev
```
http://localhost:3000 を開く。止めるときは Ctrl+C。

Cron を手で動かすとき（ターミナル3。Emulator と `npm run dev` が動いている間）。ふつうは、画面で請求日が明日（または7日後）になるサブスクを登録してから、`runDate` を付けずに呼ぶ：
```bash
curl -H "Authorization: Bearer dummy-cron-secret-for-emulator-only" "http://localhost:3000/api/cron/daily"
```
`dummy-cron-secret-for-emulator-only` は `.env.development.local` の CRON_SECRET（ローカル用のダミー）。本番の鍵は使わない。
- `?runDate=2026-11-04` のように日付を決めることもできる（`.env.development.local` の `ALLOW_CRON_RUNDATE_OVERRIDE=true` のときだけ。ローカル専用）。ただし、画面で登録したデータには使わない。次の請求日は本当の今日から計算され、Cron は今日より前の請求日しか計算し直さないので、日付を決めても、ふつうは通知が0件になる。`runDate` は、`seedUser`・`seedSubscriptions` で置いたテストデータ（Emulator のテスト）と組み合わせるときだけ使う。

## 5. テスト
`subwatch/` で、**4 の Emulator と `npm run dev` を止めてから**（`npm run test:emulator` は、自分で Emulator を起動して、ポート 8080・9099 を使う）：
```bash
npm run typecheck
npm test
npm run test:emulator
```
`npm run test:e2e` も同じ場所で実行できる（動いている `npm run dev` と、4で起動した Emulator は止めてから。自分で起動して、終わったら止める）。通れば、環境は使える状態。
- 11/12 は、04-01 の段階1〜2（ビルドが通る土台）しか main に入っていないので、`npm run typecheck`・`npm run build` が通ればよい（`npm test`・`npm run test:emulator`・`npm run test:e2e` は、段階3〜4 のテストの土台を使うので、まだ動かない）。全部が通るのは、04-01 の段階3〜4 が main に入った後（11/17 の2限の終わりまでに Pull Request が出て、3限の初めの30分で星凪が確認し、創大がマージする）。11/17 の 04-05・04-06 は、3限（段階3〜4 のマージの後）に `git merge main` で段階3〜4 を取り込んでから、画面のテストを書く（テストの共通部品は自分で作らない）。段階1〜2 が 11/12 に入らなかったときは、11/17 の1限に入り、段階3〜4 は2〜3限に入る。

## 6. 公開用の鍵（担当だけ。ローカルの開発には使わない）
鍵は `~/secrets/` に置き、画面に出さず、AIに貼らない。最初に、自分だけが読めるフォルダを作る：
```bash
mkdir -p ~/secrets && chmod 700 ~/secrets
```
- サービスアカウントキー（結愛）：手順書 01 の 5。キーは1回だけ作る。ダウンロードしたら、すぐ `~/secrets/` に移す（ダウンロードのフォルダは `xdg-user-dir DOWNLOAD` で分かる。`~/Downloads` か `~/ダウンロード`。ホーム〔`$HOME`〕だけが出るときは、`ls -d ~/Downloads ~/ダウンロード` で有る方を使う。そこに残さない）。Vercel に入れる値は `base64 -w0 ~/secrets/subwatch-key.json > ~/secrets/key-base64.txt`。作ったら `test -s ~/secrets/key-base64.txt && echo OK` で OK と出ることを確かめる（手順書 01 の 5 で済ませていれば、もう一度作らない）。創大が Cron のリセットに使うキーは、創大が手順書 01 の 5 と同じ手順で自分で作る（人から受け取らない）。
- 04-12（結愛）：`subwatch/` の中で `npx --yes web-push@3.6 generate-vapid-keys --json > ~/secrets/vapid.json && chmod 600 ~/secrets/vapid.json`（`--yes` を付けないと、入れてよいかの質問の文が JSON に混ざる）。作ったら `jq -e .publicKey ~/secrets/vapid.json > /dev/null && echo OK` で OK と出ることを確かめる。鍵は1回だけ作る（作り直すと、購読した端末に届かなくなる）。Vercel に貼るのは 11/19 の4限の最後の15分（結愛のパソコン。創大がログイン。04-11・04-12 の時間に含む。手順書 02 の 5）。このファイルは JSON（publicKey と privateKey の2つが入っている）なので、ファイルごとコピーして Vercel に貼らない。貼るときは、下の `jq` で1つずつ取り出す。
- 04-14（創大）：`openssl rand -hex 32 | tr -d '\n' > ~/secrets/cron-secret.txt && chmod 600 ~/secrets/cron-secret.txt`（最後の改行を入れない。自分だけが読めるようにする）。Vercel に貼るのは 11/24 の4限の最後の15分（創大のパソコン。創大がログイン。どちらかが休んだら 11/25 の午前。手順書 02 の 5）。
- Vercel へは、鍵を持つ人（サービスアカウントの鍵と VAPID は結愛、CRON_SECRET は創大）のパソコンで入れる。創大が Vercel にシークレットウィンドウでログインし、鍵を持つ人が自分のクリップボードから貼る。終わったら創大がログアウトする（鍵をチャット・ファイル・USB で渡さない。手順書 02 の 4・5）。
- Vercel に貼るときも、鍵を画面に出さない。`cat` で表示しない（画面共有中や、AIのセッションの中では特に）。クリップボードにコピーして貼る：
  ```bash
  sudo apt install -y xclip jq                                   # 最初に一度だけ（結愛は 11/12 の2〜4限に、xclip・jq の導入と鍵の Base64 化まで済ませておく。貼るのは 11/17 の2限の初回デプロイ）
  xclip -selection clipboard < ~/secrets/key-base64.txt          # 中身を表示せずにコピーする。cron-secret.txt も同じ
  jq -r .publicKey ~/secrets/vapid.json | tr -d '\n' | xclip -selection clipboard    # NEXT_PUBLIC_VAPID_PUBLIC_KEY に貼る値
  jq -r .privateKey ~/secrets/vapid.json | tr -d '\n' | xclip -selection clipboard   # VAPID_PRIVATE_KEY に貼る値
  ```
  Wayland の画面（Ubuntu の標準など）で xclip が効かないときは、`sudo apt install -y wl-clipboard` を入れ、`xclip -selection clipboard` の代わりに `wl-copy` を使う（例：`wl-copy < ~/secrets/key-base64.txt`、`jq -r .publicKey ~/secrets/vapid.json | tr -d '\n' | wl-copy`）。
  結愛は 11/12 の2〜4限に（創大は 11/24 の前に）、クリップボードが使えるかを試しておく：`echo test | xclip -selection clipboard && xclip -selection clipboard -o`（Wayland なら `echo test | wl-copy && wl-paste`）で test と出れば使える（Deploy Hook の URL を写すときに `xclip -o`／`wl-paste` を使う。手順書 02 の 4 の B）。
  どちらも使えないときは、ファイルをテキストエディタで開いてコピーする（画面共有はしない。vapid.json は、publicKey・privateKey の " " の中の値だけをコピーする）。貼った後は、別の文字をコピーしてクリップボードを上書きする。
- Deploy Hook の URL（結愛。11/17 の2限に星凪が作る。手順書 02 の 4 の B と 5-2）：画面のコピーボタンで、自分の `~/secrets/deploy-hook.txt` に写し、`chmod 600 ~/secrets/deploy-hook.txt` にする。URL を知っていれば誰でも本番のデプロイを動かせるので、鍵と同じに扱う（チャット・AIに貼らない）。11/17 には叩かない。叩くとき（11/18 の1限の確認から）は `curl -fsS -X POST "$(cat ~/secrets/deploy-hook.txt)" > /dev/null && echo OK`。
- 本物の値は `~/secrets/` の中だけに置き、リポジトリの中（`subwatch/.env.local` を含む）には置かない。`subwatch/.env.local` は作らない。
- 創大が手で Cron を動かすとき（`scripts/trigger-cron.mjs --reset`。手で動かすのは創大だけ）の値は、`~/secrets/cron.env` に置く（項目は `設定ファイル/.env.local.example`）。鍵の値は、画面に出さずに書き足す（自分のキーは、先に手順書 01 の 5 と同じ手順で `~/secrets/` に移して `base64 -w0` で `~/secrets/key-base64.txt` にし、`test -s ~/secrets/key-base64.txt && echo OK` で OK と出ることを確かめておく）：
  ```bash
  touch ~/secrets/cron.env && chmod 600 ~/secrets/cron.env
  printf 'FIREBASE_SERVICE_ACCOUNT_JSON=%s\n' "$(cat ~/secrets/key-base64.txt)" > ~/secrets/cron.env    # 1行目は > で作り直す（やり直しても行が重ならない）
  printf 'CRON_SECRET=%s\n' "$(cat ~/secrets/cron-secret.txt)" >> ~/secrets/cron.env
  ```
  ほかの値（`NEXT_PUBLIC_FIREBASE_PROJECT_ID` など。秘密でない）は、上の2行の後にエディタで書き足してよい（上の2行をやり直したときは、書き足し直す）。動かすときは、`subwatch/` で `node --env-file=$HOME/secrets/cron.env scripts/trigger-cron.mjs`（引数は手順書 04 の B）。
- ブラウザのチャットのAIには、`~/secrets` の中身やエラーに出た鍵を貼らない。自動で止める仕組みがないので、自分で気をつける。

## 7. うまくいかないとき
| 症状 | 対処 |
|---|---|
| Emulator が起動しない | `java -version` を確かめる。ポート 8080・9099 を使っているものを止める |
| 全 API が 401 | 本物の値でビルドした `.next` を Emulator で使っている。`rm -rf .next` して `npm run dev` |
| 規約の同意画面から進めない | `.env.development.local` の版と、登録時の版が違う。Emulator を再起動する |
| 画面テストが 8080 で失敗する | 前回の Emulator（java）が残っている。`fuser -k 8080/tcp` |
| `firebase/firestore` を入れてしまった | ブラウザから Firestore は使わない。`CLAUDE.md` を見直す |
