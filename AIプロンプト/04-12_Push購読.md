- アイコンは `設定ファイル/icons/` の3枚を `public/` にコピーする（作らない）
- `public/manifest.webmanifest` に必ず入れる値：`name` と `short_name` は "SubWatch"、`start_url` と `scope` は "/"、`display` は "standalone"、`background_color` と `theme_color`、`icons` の 192 と 512（`設定ファイル/icons/` のもの）。`app/layout.tsx` が manifest と `apple-touch-icon` を指定していることを確かめる（04-01 が書いている。無ければ報告する）
- `public/sw.js` の決まり：install で `self.skipWaiting()`、activate で `clients.claim()` を呼ぶ。notificationclick では、通知の `data`（04-15 が showNotification で入れる `{ url, notificationId }`）の `url` を読み、開いている画面があれば `WindowClient.navigate(url)` をしてから `focus()` する。navigate が失敗したときや、開いている画面が無いときは `clients.openWindow(url)` で開く。開く `url` には `?from=push` を付ける。`url` がアプリの中のパス（`/` で始まる、同じオリジン）でなければ、ホームを開く（API共通仕様 B96）（受信の処理は 04-15 が足す）
- `pushsubscriptionchange` は扱わない（Service Worker は ID トークンを持たないので、サーバーに送れない）。購読が変わると、利用者が S-09 のスイッチをもう一度オンにするまで Push は届かない。これは分かっている制限として報告に書く
- `components/settings/PushSection.tsx`（④〜⑦）。⑤の表示：ブラウザに購読があるときは GET /api/account を読み、この端末の購読の ID（endpoint の sha256 を16進64文字にしたもの＝webPushId）が `pushSubscriptionIds`（04-05 が返す）に無ければ、ブラウザの購読を解除して「この端末で受け取る：オフ」と表示する。確かめる間は「確認中…」。読めなかったときは、ブラウザの判定のままにする（API共通仕様「S-09のPush状態」）。④のスイッチの登録・解除が失敗したら、スイッチを元へ戻す。オフにするときは、先に DELETE /api/push/subscribe を呼び、成功してからブラウザの購読を解除する（サーバーが失敗したら、ブラウザの購読を残してオンのまま）。`isGateError` のときは文を出さない（ゲートが画面を切り替える）。それ以外の失敗は、オンにするときは「登録できませんでした。もう一度お試しください」、オフにするときは「解除できませんでした。もう一度お試しください」（画面設計書 S-09 の文を正とする）。④を押したときの文は④のすぐ下に出すが、同じ文が⑤（状態か案内）に出ているときは④の下には出さない（同じ文を2回見せない）。⑦には「ホーム画面に追加したアプリは Safari とログインの状態を共有しないため、追加した後にもう一度ログインしてください」も書く。登録で送る `userAgent` は、画面で512文字までに切る（サーバーは512文字を超えると400）。Service Worker が動き出すのを待つのは10秒まで（過ぎたら「登録できませんでした…」。決まりの一覧 C-14）
- このタスクは Should（決まりの一覧 B-5）。Web Push を削ると決めたときは、統合の日にまとめ役が S-09 の枠で `PushSection` を外し、⑥（通知タイミング）だけを残して文を「請求日・最終無料日の7日前と1日前に、通知センターでお知らせします（毎日、日本時間9時台（遅れると11時台か18時台）に判定）」にする。外しやすいように、⑥は `components/settings/NotificationTiming.tsx`（props は `withoutPush?: boolean`。true のときは削ったときの文。題は図のとおり「通知タイミング（固定）」）に分け、`PushSection` の中で使う。削るときは、S-09 の枠の `<PushSection />` を `<NotificationTiming withoutPush />` に替えるだけにする（AuthProvider の import・/api/push/subscribe・sw.js・manifest は残してよい。購読が無い端末では何も呼ばない。決まりの一覧 B-5）。
- `lib/push-client.ts` で `registerBeforeLogout` を呼び、ログアウト時に購読を解除する処理を登録する。処理は、DELETE /api/push/subscribe を呼んだ後、その結果（成功・失敗・409・時間切れ）にかかわらず、ブラウザの購読（`unsubscribeBrowserPush()`）を必ず解除する（共用の端末で、前の人の通知が届かないように）。DELETE の応答を待つのは2.5秒まで（`logout()` 全体の上限の3秒の中で、残りの時間でブラウザの購読を解除するため。`api()` の `timeoutMs` は使わず、待つのをやめるだけ。決まりの一覧 C-7）。ブラウザに購読が無い端末では、DELETE /api/push/subscribe を呼ばない。このログアウトの DELETE /api/push/subscribe は `api(…, { skipGate: true })` で呼び、`onApiGate` を呼ばせない（409 ACCOUNT_NOT_INITIALIZED などが返っても。S-09 と S-13 のどちらからのログアウトでも）。Vitest で、サーバーが失敗してもブラウザの解除が呼ばれることを1件確かめる。S-13 からのログアウトでも動くよう、`components/AuthProvider.tsx` に `import "@/lib/push-client"` を1行足す（AuthProvider の変更はこの1行だけ）
- `lib/push-client.ts` に、サーバーを呼ばない解除 `unsubscribeBrowserPush()`（ブラウザの購読だけを解除する。失敗しても例外を投げない）も作り、`lib/logout.ts` の `registerLocalCleanup(unsubscribeBrowserPush)` で登録する（401 のサインアウトの前に 04-05 の AuthProvider が、アカウント削除の後に 04-17 が、`runLocalCleanup()` で呼ぶ）
- `tests/emulator/push.test.ts`、`tests/unit/push-client.test.ts`。購読を Firestore に直接置く `seedPushSubscription(uid, fields?)` を `tests/emulator/helpers.ts` に足す（04-15 も使う）。Push の画面テスト（No.63・64。`tests/e2e/push.spec.ts`）は、`page.addInitScript` でブラウザの `pushManager`（と通知の許可）を差し替え、偽の購読を返す（本物の Push サービスに通信しない。開発ルール「テストの置き場所」）。No.64 は、この形で S-09 を開き、GET /api/account を `mockApi` で作って確かめる（⑤の判定は `lib/push-client.ts` の関数に置き、`tests/unit/push-client.test.ts` でも確かめる。`unsubscribeBrowserPush()` も、ここで確かめる）。No.63 の Push の部分（401 UNAUTHENTICATED を受けたとき、偽の購読の解除が呼ばれ、サーバーの API は呼ばれない）も、同じファイルに足す（04-05 の `auth.spec.ts` は変えない）。Vitest で、ブラウザに購読が無いときはログアウトで DELETE /api/push/subscribe を呼ばないことも1件確かめる（決まりの分岐のテスト）。サーバー側の 503 の検証は、画面テストと分けて、単体テスト（`tests/unit/` か `tests/emulator/`）で行う。本物の通知の許可と購読は、パソコンの Chrome で手で確かめる。ブラウザの購読を送るときは、必要な項目（endpoint、keys.p256dh、keys.auth）だけを選んで送る（`toJSON()` には `expirationTime` が付くので、そのまま送ると未知のキーで 400 になる）
