# AIプロンプトの使い方

各自がAIを使って担当機能を作るときの指示です。使うAIは人によって違ってかまいません（Claude、ChatGPT など）。リポジトリ直下の開発ルール（`CLAUDE.md`・`AGENTS.md`。同じ内容）で、どのAIも同じルールで動きます。

## 使い方
1. その日のタスクのファイルを開く。
2. ブランチを作り、AIを準備する。
   - Claude Code、Codex などのコマンドのAI：リポジトリの直下で起動する（開発ルールを自動で読む）。
   - ブラウザのチャットのAI：最初に `CLAUDE.md` と `docs/開発ルールの詳細.md`（CLAUDE.md の続き）の全文を貼り、読むようにと書かれた設計書の該当シートも `設計書テキスト/` から貼る。返ってきたコードは、自分でファイルにする。チャットのAIはリポジトリを見られず、コマンドも実行できないので、次も自分で行う：
     - 図（`設計書図/` の PNG）を添付する。
     - そのタスクが使う既存のファイルを貼る（共通部品のうち使うものと、プロンプトに名前のあるファイル。例：04-08 なら `components/SubscriptionForm.tsx`）。
     - `npm run typecheck` などのコマンドは自分で実行し、結果を貼って直させる。
     - 「`設定ファイル/` からコピーする」と書かれたファイルは、自分でコピーする。
     - 統合では、`git diff main...ブランチ名` の出力を貼る。
3. 「AIに渡すプロンプト」を貼る。作る前に出てくる一覧を確認してから、進めさせる。
4. 「人が確かめること」と `確認チェックリスト.md` を自分で確かめる。
5. Pull Request を出し、副担当の確認を受ける。

## 守ること
- 秘密の値（サービスアカウントキー、VAPID 秘密鍵、CRON_SECRET、Deploy Hook の URL）をAIに貼らない。
- **Codex など Claude Code 以外のAIを使う人へ：** `.claude/settings.json` の deny（`~/secrets`・`.env.local` などを読ませない、`firebase deploy`・`vercel --prod` を動かさない設定）は Claude Code にしか効かない。Codex は `AGENTS.md` を読むが、この止める仕組みは無い。AIに `firebase deploy`・`vercel`（`npx vercel` を含む）を実行させない、`~/secrets` の中や `.env.local` を読ませない。AIがこれらのコマンドを出したら、許可せずに止める（`firebase deploy` は創大、Vercel の操作は星凪が人の手で行う）。
- 動作見本（`Work/app-src`。プロンプトと設計書だけで AI が作れるかを試すために作ったもの）をリポジトリに入れない。AIにも読ませない。結愛のパソコンにだけ置き、見てよいのは、自分の Pull Request を出した後に結愛と一緒にだけ（決まりの一覧 D-5）。
- `_旧版/` は以前の方式の指示です。使いません。チームのリポジトリにも、配布フォルダにも入れません。
