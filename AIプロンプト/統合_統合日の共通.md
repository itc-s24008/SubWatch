統合日は、午前3時間が全員の統合。午後3時間のタスク（例：11/19 の 04-12、11/25 の 04-17）の中に、副担当の確認0.5時間を含める（午後のタスクは2.5時間で終わる大きさ）。副担当の0.5時間は Pull Request を読むことと5分の口頭確認・記録だけで、異常系のテストは統合日には足さない（12/1 のテスト仕様書〔04-24〕に、創大が全機能分の異常系のケースを書き、各機能のテスト担当が 12/2 のテストの前に読んで〔テストの時間に含む〕、約20件の中で行う。自動テストのコードとして足すのは 12/3〜12/9 のバグ修正の中。`テスト_異常系の追加.md`）。まとめ役の午後の副担当の確認は、その日の「統合の残り」の時間の中で行う。

マージは、まとめ役が統合用のブランチ（main から作る。例：`git switch main && git pull && git switch -c integration-1119`）の上で行い、作った本人が立ち会う。ぶつかった箇所は、両方の担当者で直す。全部入れてテストが通ったら、統合用のブランチの Pull Request を1本出して main に入れる（マージボタンは星凪。まとめ役の星凪が休んだ統合日〔11/25〕は、代行〔創大〕が統合を進め、マージと Deploy Hook〔本番への反映。手順書 02 の 5-2〕は結愛が行う。Deploy Hook の確認〔11/18〕が通っていないときは、11/25 のデモはローカル〔Emulator〕で行い、12/1 は公開を 12/3 に延ばす。12/1 に星凪が休んだら、公開の点検〔04-23〕ができないので、公開を 12/3 に延ばし、12/3 の1〜2限に星凪が 05-04 の時間で点検する〔05-04 の残りは3時間〕。統合日にまとめ役が休んだら、WBS の副担当が代行する）。手順は `手順書/05_PullRequestと統合.md`。
