## 推測した箇所

| 場所 | 推測した内容 | 理由 |
|---|---|---|
| `nthBillingDate` | 0 回目は請求日（firstBillingDate）そのもの。endOfMonth で請求日が月末日でないデータは、0 回目をその月の末日にする | 機能設計書「共通ロジック」B4 の手順1〜2と4 から |
| `nextBillingDate`・`billingDatesInRange` | 0 回目から順に調べるが、今日（from）の月より前にある回は数えずに飛ばす（結果は同じ） | 2000 年の請求日から 2100 年を求めるときも、すぐ終わるように |
| `annualAmount`・`monthlyEquivalentTotal` | 数でない値（文字列・NaN・無限大）だけを RangeError にする。負の値や範囲（0〜10,000,000）は調べない | 指示書は「数でない金額は RangeError」とだけ。範囲は API の入力の検証が行う |
| `isValidDate` | 「YYYY-MM-DD の形で、実在する日付」だけを見る。年の範囲（2000〜2100）は調べない | 指示書のとおり（範囲は呼ぶ側が文字列の比較で調べる） |
| `daysInMonth` | 年と月が整数でない、または月が 1〜12 でないときは RangeError | 指示書の「整数でない n は RangeError」に合わせた |
| `nextBillingDate` の `today`、`billingDatesInRange` の `from`・`to` | 壊れた日付なら RangeError | 「壊れた日付は RangeError」を、どの引数にも当てはめた |
| `tests/unit/billing.test.ts` | テスト一覧の No.1・2・3・6・25 のほかに、テストデータ（基準日 2026-11-04）の5件の次回請求日と、年額換算 156,600 円・月額換算 13,050 円、要件定義書「共通ルール」B9 の例（1,980 円）を、番号なしのテストで確かめた | 指示書の「番号なしのテスト」の中で、設計書に期待値があるものを使った |
